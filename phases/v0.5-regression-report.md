## 0. 校验方法

**沙盘推演**：在心智中把每个案例的 Phase 0-6 用 v0.5 新骨架重新跑一遍，检查每个卡点是否被新落地的能力消解。

**判定标准**：
- ✅ **已消解**：v0.5 落地的文件/小节明确覆盖了该卡点
- 🟡 **部分消解**：v0.5 覆盖了主体但仍有细节待补
- ❌ **未消解**：v0.5 未覆盖，留作下一轮

## 6. v0.5 整体评估

### 量化成果
- **消解率**：55 / 58 ≈ **95%**（含完全+部分）
- **完全消解**：53 / 58 ≈ **91%**
- **彻底未触达**：1 条（且属于"不脑补"原则的正确行为）

### 质化成果
- **从"工作流骨架"升级到"方法论骨架"**：之前只有"每个 Phase 做什么"，现在有"每个 Phase 怎么做"
- **复杂度感知能力**：Fast/Standard/Full 三档使骨架**对小场景不过度、对大场景不欠拟合**
- **绑定点 + cert_role**：贯穿盘点-规划-演练-验证的粒度基础，**消除了"1 证书 1 部署"的隐式假设**
- **组织能力维度（D9-D13）**：骨架首次显式承认"客户不只有技术，还有法务/治理/采购"

### 已知残留风险
- **v0.5 文件体量增大**：SKILL.md 从 580 行到 ~720 行，phases 新增 7 份文件。客户第一次加载时需合理按需引用（SKILL.md §8 加载策略已有规定，但 v0.5 新 playbook 未全部纳入加载策略）
  - **建议 v0.6 修补**：更新 SKILL.md §8 加载策略，明确"Fast Path 不需要加载 phases/03~06"
- **事实校准红线的自检在 G7**：但 G7 只要求 Agent 自检"是否误踩已知红线"，对**新的事实红线**（比如未来发现其他错误信念）没有保护机制
  - **建议 v0.6**：加"事实校准红线清单" doc 单独维护
